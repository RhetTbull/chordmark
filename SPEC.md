# Chordmark Shortcut Chord Clipboard Utility — Product Specification

## 1. Overview

A lightweight macOS menu bar utility for capturing a keyboard shortcut, rendering it using Apple’s standard modifier symbols, and copying the result to the clipboard.

Example:

`Shift + Command + G` → `⇧⌘G`

The utility should appear only when needed and disappear immediately after copying.

## 2. Core user flow

1. User activates the utility through either:
   - A configurable global hotkey.
   - The menu bar icon.
2. A small floating capture window opens and receives keyboard focus.
3. User presses a shortcut chord.
4. The rendered shortcut appears immediately.
5. User clicks Copy or presses Return.
6. The formatted shortcut is copied to the system clipboard.
7. The window dismisses and the previously active app regains focus.
8. Pressing Escape dismisses without changing the clipboard.

## 3. Functional requirements

### Capture

- Capture one simultaneous key combination per session.
- Support:
  - Control
  - Option
  - Shift
  - Command
  - Function/Globe where available
  - Letters and numbers
  - Punctuation
  - Function keys
  - Arrow and navigation keys
  - Space, Tab, Return, Enter, Delete, Forward Delete, and Escape
  - Numeric keypad keys
- The capture field should begin listening automatically when the window opens.
- Repeated key events must not duplicate characters.
- Modifier keys should be tracked by physical key state, not by the text generated by the keyboard layout.
- A new chord replaces the previously captured chord.
- Modifier-only combinations may be supported, but are optional for version 1.

### Modifier ordering

Render modifiers in Apple HIG order:

1. Control — `⌃`
2. Option — `⌥`
3. Shift — `⇧`
4. Command — `⌘`

For example:

- `Command + Shift + G` → `⇧⌘G`
- `Control + Option + Command + P` → `⌃⌥⌘P`

Do not insert spaces between symbols. Use the user-visible key label after the modifiers.

Apple specifies this ordering in its [Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/keyboards).

### Special-key rendering

Use conventional macOS symbols where appropriate:

| Key | Output |
|---|---|
| Escape | `⎋` |
| Tab | `⇥` |
| Return | `↩` |
| Enter | `⌅` |
| Space | `Space` or `␣` |
| Delete | `⌫` |
| Forward Delete | `⌦` |
| Up Arrow | `↑` |
| Down Arrow | `↓` |
| Left Arrow | `←` |
| Right Arrow | `→` |
| Function | `fn` |

The representation should be centralized in a key-to-symbol mapping so it can be adjusted later.

## 4. Capture window

### Appearance

- Floating, compact window approximately 320 × 150 points.
- Centered on the active display or positioned near the menu bar.
- Native macOS appearance with light/dark mode support.
- No document window chrome.
- Clear title such as “Capture Shortcut”.
- Large, prominent output field.
- Small Copy button.
- Optional Clear button.
- Copy button disabled until a chord is captured.

Suggested layout:

```text
Capture Shortcut

          ⇧⌘G

                 [ Copy ]
```

### Behavior

- Open directly into capture mode.
- Keep the window above normal application windows while active.
- Do not open a Dock icon.
- Do not show a persistent main window.
- Copying should close the window within approximately 100 ms.
- Escape closes the window without modifying the clipboard.
- Clicking outside the window may dismiss it, configurable as a preference.
- Opening the utility again starts with a blank capture state.

## 5. Menu bar interface

The menu bar menu should contain:

- Capture Shortcut…
- Configure Hotkey…
- Launch at Login
- About
- Quit

The menu bar icon should be a simple native symbol, such as a keyboard or command symbol.

The global activation hotkey must be configurable. The app should avoid claiming a shortcut already used by another application where possible.

## 6. Clipboard behavior

- Copy the rendered representation as plain Unicode text.
- Do not place rich text, HTML, or formatting on the clipboard in version 1.
- Do not paste automatically into the originating application.
- Preserve the existing clipboard if the user dismisses with Escape.
- On successful copy, briefly show standard macOS feedback if appropriate, but avoid a notification that interrupts the user.

## 7. Focus and application restoration

When the capture window opens:

- Remember the previously active application.
- Temporarily make the capture window key so it can receive events.
- After copying or dismissal, close the window.
- Reactivate the previously active application when practical.

The app must not remain frontmost after the operation.

## 8. Permissions and privacy

The core workflow should require no Accessibility permission, Input Monitoring permission, account, analytics, or network access.

Recommended implementation:

- Use a standard system global-hotkey registration mechanism for the activation shortcut.
- Capture keyboard events only while the app’s own window is focused.
- Write directly to `NSPasteboard`.

No keystrokes should be logged, stored, transmitted, or included in crash reports.

## 9. Suggested implementation architecture

- Swift 5.9 or later.
- SwiftUI for the capture window and menu bar UI.
- `MenuBarExtra` or an `NSStatusItem` for the menu bar presence.
- An `NSPanel` or borderless `NSWindow` for the floating capture window.
- AppKit keyboard event handling for reliable key-code and modifier-state capture.
- A small `ShortcutFormatter` type responsible for:
  - Modifier normalization.
  - HIG ordering.
  - Key-code-to-symbol conversion.
  - Output generation.
- Store only preferences:
  - Activation hotkey.
  - Launch-at-login setting.
  - Window positioning/appearance preferences, if needed.

Keep dependencies to zero if possible.

## 10. Edge cases

- If the user presses an unsupported key, show its readable name rather than silently ignoring it.
- If no key is captured, Copy remains disabled.
- If the activation hotkey is pressed while the capture window is open, it should not overwrite the captured chord.
- Secure input fields in other apps should not affect the utility because capture occurs only in the utility’s own window.
- Keyboard layouts should affect the displayed character where possible, but modifier symbols must remain language-independent.
- Distinguish Return from Enter when the system exposes them separately.
- Avoid treating key auto-repeat as multiple captures.

## 11. Acceptance criteria

The first release is complete when:

- The app launches as a menu bar utility with no Dock presence.
- The capture window opens from the menu bar.
- A configurable global hotkey opens the same window.
- Pressing Shift-Command-G displays `⇧⌘G`.
- Modifiers always appear in Control, Option, Shift, Command order.
- Copy places the exact rendered string on the clipboard and dismisses the window.
- Return performs the same action as Copy.
- Escape dismisses without changing the clipboard.
- The previous application regains focus after dismissal.
- The app requests no Accessibility or Input Monitoring permission.
- The app performs no network activity and stores no captured shortcuts.
- The utility remains idle when not in use and consumes minimal CPU and memory.

## 12. Possible future enhancements

- Support multi-step sequences such as `⌘K`, then `⌘T`.
- Copy alternate formats, such as `Shift-Command-G` or `⇧⌘G`.
- Automatically paste instead of only copying.
- Provide a configurable symbol set.
- Add a history of recently captured chords.
- Add a command-line interface or Services integration.
- Export captured shortcuts as Markdown.
